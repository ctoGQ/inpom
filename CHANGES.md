### 2. ✅ API Endpoints

#### POST `/api/invoices` - Создание инвойса
- Валидация: amount (> 0, ≤ 999999.99)
- Валидация: description (обязателен, 0-500 символов)
- Валидация: expiryMinutes (1-43200)
- Возвращает: QR код + paymentUrl
- Ошибки: User-friendly сообщения

#### POST `/api/invoices/pay` - Обработка платежа
- Проверка: платник ≠ автор
- Проверка: инвойс не истек
- Проверка: инвойс не оплачен
- Проверка: достаточно баланса
- Действия:
  - Создает 2 транзакции (payment_sent для платника, payment_received для автора)
  - Обновляет балансы обоих пользователей
  - Автоматически создает карту автору если не существует
- Ошибки: Детальные сообщения о причине ошибки

#### GET `/api/balance` - Получение баланса
- Возвращает текущий баланс пользователя
- Используется перед платежом для проверки

### 3. ✅ Страницы и компоненты

#### `/mycabinet/invoices/[id]` - Просмотр созданного инвойса
- **Доступ**: Только для создателя инвойса
- **Функции**:
  - Отображение инвойса с QR кодом
  - Копирование URL в буфер обмена
  - Скачивание QR как PNG
  - Кнопка для просмотра страницы оплаты (как видит платник)
  - Кнопка возврата на транзакции

#### `/mycabinet/pay-invoice/[id]` - Оплата инвойса
- **Доступ**: Для любого авторизированного пользователя (кроме автора)
- **Проверки**:
  - Редирект на signin если не авторизирован
  - Проверка что не платит свой инвойс
  - Проверка статуса инвойса (не оплачен, не истек)
- **Функции**:
  - Отображение деталей инвойса
  - Загрузка баланса пользователя
  - Компонент PaymentConfirm для оплаты
  - Информационные сообщения о статусе

#### `/mycabinet/transactions` - История транзакций
- **Все транзакции** пользователя с сортировкой по дате
- **Умные ссылки на инвойсы**:
  - payment_sent → /mycabinet/pay-invoice/[id] (статус оплаты)
  - payment_received → /mycabinet/invoices/[id] (просмотр инвойса)
- **Отображение**:
  - Тип транзакции с форматированием
  - Сумма с цветовым кодированием (зелено для входящих, красно для исходящих)
  - Дата и время
  - Кнопка для открытия связанного инвойса

#### Компонент `PaymentConfirm`
- Загрузка баланса перед платежом
- Отображение достаточности коштів (цветовой индикатор)
- Обработка платежа с loading state
- Детальные сообщения об ошибках
- Редирект на `/mycabinet/transactions` после успешной оплаты
- Обработка состояний: expired, already_paid

### 4. ✅ Механизмы безопасности

#### На уровне middleware
- Все `/mycabinet` маршруты защищены
- Проверка валидности session token
- Проверка срока истечения сессии (expires_at > NOW())
- Редирект на signin при отсутствии сессии

#### На уровне страниц
- `getSessionCustomer()` на всех защищенных страницах
- Проверка что пользователь владает инвойсом (для authors)
- Проверка что пользователь не платит свой инвойс

#### На уровне API
- Все проверки бизнес-логики
- Не полагается на клиентскую валидацию
- Транакции в БД обновляются только при успехе

## 🔍 Ключевые особенности

### Двусторонний учет
- Для каждого платежа создаются 2 транзакции
- Платник видит payment_sent (дебет)
- Автор видит payment_received (кредит)
- Оба видят в истории с правильным направлением

### Интеллектуальная навигация
- Система автоматически определяет какую ссылку показывать
- Платник видит статус оплаты через /pay-invoice
- Автор видит детали инвойса через /invoices
- Всегда показывается правильная информация для пользователя

### Защита от ошибок
- Валидация на 3 уровнях (клиент, middleware, API)
- Проверка баланса перед платежом
- Проверка что инвойс не истек
- Проверка что инвойс не оплачен дважды
- Проверка что платник ≠ автор

### Хороший UX
- Подробные сообщения об ошибках
- Цветовой индикатор баланса (зеленый/красный)
- Loading состояния при обработке
- Toast уведомления о результатах
- Автоматический редирект после успеха
